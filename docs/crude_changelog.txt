Noteworthy Changes:
	* Game now runs on a state chart system
		* Split GlobalRuntime into GlobalTools and GlobalState
			> "Runtime" implies the class runs code, which is not true
			> G.Runtime did not follow the single-responsibility principle
			> GlobalState is for scene manager, i/o state, and syncing (rng)
			> GlobalTools is for unit conversions and engine/library gimmicks
	* Merged global classes which have similar roles
		- Removed GlobalGamepieceTransfer (merged into LevelMap)
		- Removed GlobalBitManip (merged into GlobalTools)
		- Removed GlobalMonsterSpawner (merged into GlobalMonster)
	* Revised gamepiece teleport/anchor system
		* For debug purposes, anchors try to save their position to player file
	* Gamepiece facing direction uses an enum (cannot face diagonal/zero)
	* Revised GlobalDayCycle into GlobalClock

General Commentary:
	> Global classes go into "res://global" and include "global" in their names.
		> Exception: if the global class is part of an addon or workaround.
	
	> Functions must be separated with 2 blank lines, uninterrupted.
	> Comments before a function should explain as if it is class documentation
	> Comments in a function should say 'why'/'how' rather than 'what'/'where'
		> More like: "this line solves an edge case related to char *"  
		> Less like: [var v = 2] "this line sets v to 2"
			> I (jan Wiwijen) don't follow my own rules. This is a bad thing.
	
	> Generally, code for a thing should be inside it, or its direct controller.
	
	> This whole thing is a redo for multiple reasons including: 
		> Confusion about code and asset licensing in the GitHub repo settings
		> Following tutorials from unknown license repositories
		> Inconsistant file naming + bad folder structure
		> Improper credits documentation
		> Outdated version of Godot
		> Setting up is the best part. Expanding & bugfixing though...?
	
	> No sources should be less permissive than a BSD 3-Clause license. 
	> Everything in here should be both free as in libre, and free as in moneys.
	> All assets not made for this project need proper credit (CC-BY-4.0, SIL), 
	> or to be PD/CC-0.
